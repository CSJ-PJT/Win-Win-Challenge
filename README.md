# 도착완성: 안심동행

차량 도착과 대면 인계를 구분해, 보호자와 지정 담당자의 직접 확인을 기록하는 돌봄 이동 지원 앱입니다.

> 합성 데이터 기반의 공모전 프로토타입입니다. 실제 이용자·기관·GPS·속도·기어를 사용하지 않습니다. 대면 확인은 사람의 진술을 기록하며 실제 인수 사실이나 안전을 자동 보장하지 않습니다.

## 실행

### 설치 없는 브라우저 시연

Node.js 22 이상에서 `npm run bundle`을 실행하고 `dist/handoff-demo.html`을 최신 Chrome/Edge로 엽니다. 별도 서버 없이 한 기기에서 세 역할을 조작합니다. 제출 패키지에는 이미 생성한 단일 HTML을 포함했습니다.

### 여러 창을 연결하는 로컬 서버

```bash
npm test
npm start
```

`http://127.0.0.1:8080`을 엽니다. 역할별 창은 `/vehicle`, `/facility`, `/guardian`입니다. 같은 서버의 이동 건을 공유합니다. 외부 npm 패키지는 필요하지 않습니다. Windows에서는 `start-demo.cmd`, macOS/Linux에서는 `sh start-demo.sh`도 사용할 수 있습니다.

기본 포트가 사용 중이면 `PORT=8081 node server.js`로 변경합니다. PowerShell에서는 `$env:PORT=8081; node server.js`입니다. 상태는 `.data/demo.json`에 저장합니다.

**인터넷에 공개하거나 실제 개인정보를 입력하지 마세요.** `/api/bootstrap`은 로컬 가상 역할 토큰을 제공하며 운영 인증이 아닙니다. 서버는 루프백 바인딩, Host·Origin 검사, 역할별 API 검사, 상태 버전 충돌 및 요청 중복 방지를 적용했습니다. 파일 저장은 단일 프로세스 시연을 전제로 하며 운영 DB나 다중 서버를 대신하지 않습니다.

### Android APK

**파일:** `apk/WinWin_안심동행_release.apk`

Android 9(API 28) 이상과 최신 Android System WebView가 필요합니다. Android 15(API 35) 일반 에뮬레이터와 WebView 124에서 설치·실제 화면 렌더링을 확인했습니다. Android에서의 확인 범위는 시작 화면과 버튼 렌더링이며, 전체 인계 흐름 자동 조작 시험은 브라우저에서 수행했습니다.

```bash
adb install apk/WinWin_안심동행_release.apk
```

APK는 단일 기기 로컬 시연입니다. Node 서버와 자동 연결되지 않습니다. CI에서 일회성 시연 키로 release 서명하므로 앱 마켓 배포 키가 아닙니다. 새 빌드의 서명이 달라 업데이트가 거부되면 기존 시연 앱을 제거한 뒤 설치해야 하며, 이때 로컬 시연 기록도 삭제됩니다. 운영 서명 키는 별도로 안전하게 보관해야 합니다.

## 시연 순서

1. 시설에서 **인수 준비 완료**, 제어실에서 **P·정차 신호**를 누릅니다.
2. **출발 계획 시작 → 도착·정차 모의**를 누릅니다. 아직 인계 완료가 아닙니다.
3. **연결번호 발급**, 인계자의 직접 확인 체크·버튼을 누릅니다. 시설에서 번호를 입력하고 인수자의 직접 확인 체크·버튼을 눌러야 완료됩니다.
4. 새 시연에서 담당자 부재, 잘못된 번호, 통신 끊김을 시험합니다.
5. 경로당 자율 방문은 본인 동의를 선택한 뒤 도착만 알립니다. 인계 완료 기능을 제공하지 않습니다.

번호는 2분간 유효하고 5회 오류 시 폐기합니다. 차량 신호는 30초, 담당자 준비는 10분 동안 유효합니다. 모의 주행·구역 이탈·동의 철회·준비 해제는 진행 중인 확인을 무효화합니다. 코드 소지만으로 인수 권한을 부여하지 않습니다. 통신 복구 후 미확인 인계를 자동 완료하지 않습니다.

## 실제 구현과 미검증 영역

| 영역 | 현재 상태 |
| --- | --- |
| 인계 규칙·서버 | 구현, 자동 테스트 48개 통과 |
| 브라우저 | 정상 인계·번호 오류·담당자 부재·통신 끊김·성인 도착 전용 흐름 확인 |
| Android | Java/Kotlin 앱, 서명된 release 빌드와 일반 Android 화면 렌더링 확인 |
| AAOS | CarUxRestrictionsManager 수신·상태 불명 및 제한 시 네이티브 조작 차단 코드 작성, 차량 환경 검증 미수행 |
| Pleos | NaviHelper 3.0.5 연결·예제 경로 요청·완료/오류 콜백 코드 작성, 실제 서비스 연결 검증 미수행 |
| 모의 | 시설·인물·동의 입력·GPS·속도·기어·기관 계정 배정 |
| 미구현 | 실사용자 인증, 실제 기관 연동, SMS/푸시, 운영 DB, 실차·현장 검증 |

내비게이션 시험은 공식 문서의 예제 목적지로 별도 확인 대화상자를 거칩니다. 가상 유치원의 실제 주소가 아닙니다. 경로 요청 반환을 탐색 성공으로 표시하거나 인계 완료로 연결하지 않습니다. 주행 제한이 해제된 시험용 AAOS/Pleos 환경에서만 실행하도록 분리했습니다.

## 직접 빌드

JDK 17, Gradle 8.11.1, Android SDK 35가 필요합니다. AGP 8.9.2와 Kotlin 2.2.21을 사용합니다.

```bash
npm run bundle
mkdir -p android/app/src/main/assets
cp dist/handoff-demo.html android/app/src/main/assets/index.html
gradle -p android assembleDebug
```

Android에는 단일 번들 HTML을 넣습니다. 원본의 분리된 스크립트 파일을 복사하는 방식으로 되돌리지 마세요. release 서명은 `DEMO_KEYSTORE`, `DEMO_STORE_PASSWORD` 환경변수로 지정할 수 있습니다. 개인 배포용 키와 비밀번호를 소스에 넣지 않습니다.

## 파일 구조

```text
web/             UI와 브라우저·서버 공용 상태 규칙
server.js        Node 표준 라이브러리 HTTP 서버
test/            도메인 35개 + HTTP/API 13개 자동 테스트
android/         Android·AAOS·Pleos 어댑터
tools/bundle.js  단일 HTML 생성
docs/            검증 범위·시연 순서·공식 빈 양식
apk/             시연용 release APK
build-reports/   자동 테스트·빌드·서명·실행 증거
```

CI의 성공 판정에는 APK 생성뿐 아니라 `HANDOFF_UI_READY` 검사도 포함됩니다. 테스트 상세와 APK 해시는 `docs/BUILD_VERIFIED.md`를 확인하세요.

## 제출 전

공식 접수양식의 참가 정보·동의·서명은 제출자가 확정합니다. 연락처·서명은 저장소에 올리지 않습니다. 참가명이 정해지면 APK 파일명과 접수양식의 경로를 맞춥니다. 비공개 저장소의 심사용 계정은 공식 공지에서 확인한 뒤 접근 권한을 부여해야 합니다. 임의 계정은 초대하지 않습니다.
