# PoC 이후 앱 개발 계획

담당은 기존 PM AS-M1 한 명입니다. 11/1은 문서·Git PoC의 내부 제출 목표이며 아래는 후속 최종 제품 작업입니다. PoC의 웹·APK 상태 흐름을 유지하고 실제 운영 기능을 붙입니다.

| 순서 | 현재 코드·차이 | 다음 개발 및 완료 증거 |
| --- | --- | --- |
| 1 운영 역할·개인정보 | 로컬 bootstrap이 역할 토큰 모두 제공, guardian는 번호만 숨기고 개인 필드 일부 노출 | 기관·담당자·보호자 인증/배정과 최소 projection 구현; 다른 기관/방문 읽기·변경 거절 계약 시험 |
| 2 운영 상태·전달 | 파일 저장·폴링, 쉬운 알림/ACK와 보호자 조회는 로컬; 실제 push 미검증 | 운영 저장소·기관 동기화·동의 철회·중복 전달 정책 구현; 서비스 수신 영수증과 실제 폰 push 수신을 별도 증명 |
| 3 Android 동일 동작 | 같은 JS 자산, native 주소/지도/전화·NaviHelper/AAOS 어댑터; release 새 소스 물리 검증 미완료 | 기존 앱/데이터 보존·서명 호환 경로 확보 후 단일 대표 UI 흐름·콜드 복원; PM 자체와 독립 QA 분리 |
| 4 실제 차량·기관 | 정차·도착은 시연 신호, 실제 Pleos 서비스·차량/기관 시험 별도 | 공식 Pleos/AAOS 환경에서 제한 상태·경로 callback 검증, 기관 파일럿 동의·승하차 흐름 검증; 실제 로그/승인 |
| 5 사용성·출시 | 버튼76px와 확대 UI, 기존 에뮬레이터/PM 자체 QA | 실제 어르신·시설 사용성 시험 및 수정, 독립 QA·서명 지속성·배포/보안 검토 후 별도 공개배포 승인 |

새 기능은 화면ID·API 계약·저장 모델·웹/Android 자산을 함께 갱신합니다. 동일 소스/variant의 시험만 연결하고 다른 CI·기기·APK 결과를 합산하지 않습니다. 새 버전으로 기존앱을 삭제하거나 인증서를 강제로 교체하지 않습니다. 공식 제출·계정 초대·새 비용·공개배포는 승인 범위에 포함하지 않습니다.
